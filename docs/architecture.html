Request lifecycle (example: an agent changes a ticket's status)

  1. UI: TicketDetailPage › ActionBar calls ticketsApi.changeStatus(id, "solved") through a TanStack useMutation.
  2. Axios sends PATCH /api/v1/tickets/{id}/status with Authorization: Bearer <JWT>.
  3. Vite proxy forwards /api to localhost:8080.
  4. Middleware: request ID, logging and panic recovery run first, then a 30s timeout and CORS. Authenticate verifies the JWT and puts the Actor (id, role, name) on the request context.
  5. Handler TicketHandler.ChangeStatus decodes the JSON body and calls the service.
  6. Service TicketService.ChangeStatus runs loadAccessible (role-based visibility, otherwise 404), then CheckTransition (state machine plus role rules). In one transaction it updates tickets.status / solved_at and inserts a ticket_events row.
  7. Repository runs parameterised SQL through the pgx pool. Postgres commits.
  8. Response: the updated ticket comes back as JSON. The UI calls invalidateQueries for ticket, timeline, list, summary and notifications, which refetch immediately. Other users see the change on their next poll (default 10s).
